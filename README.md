# MJ · 两分钟原创漫剧工作台

> 当前状态：**设计大纲 / 尚未实现应用**。本仓库先完成原创漫剧路线，暂不开发影视原片解说路线。文档中的流程、接口、界面和验收要求均为待实现设计，不代表已经接入模型、完成部署或生成过成片。

## 项目要做什么

将一个原创故事构想，转化为可审核、可局部重做、费用可追踪的约两分钟中文漫剧。重点不是“一键拼出 MP4”，而是保持故事完整、角色稳定、动作与镜头连贯、声音自然，并能回到具体分镜继续修改。

首版建议采用**旁白推动剧情、关键镜头有真实人物动作、允许明确标注的设计型静态镜头**的制作模式。全动态、多人物对白和精确口型逐步扩展；不得把缺失的人物动作自动替换成静图推拉，并宣称完成原要求。

## 首版工作流

创作需求 → 多方向提案 → 剧本与动作节拍 → 角色/场景/道具设定 → 分镜与声音草案 → 动态分镜预演 → 15 秒代表性样片 → 单镜头生成与审核 → 时间线合成 → 技术质检与人工终审 → 成片及可继续编辑的项目包。

## 首版建议基线

- 中文、单集目标 120 秒；默认 9:16、1080×1920、30 fps，可在项目开始时调整。
- 单用户/单工作区优先；先用模型 API 生成素材，本地或服务器合成，不预设必须购买 GPU。
- 默认建议 2–3 个主要角色、2–3 个场景、约 18–26 个镜头，均为可修改建议，不是用户已确认的硬限制。
- 采用独立的 MJ 业务模型，选择性复用 `video-use` 等允许复用的代码；不直接拼接多个完整平台。
- **付费默认关闭**。预算、供应商、上传范围和授权未确认时，仅允许本地规划、模拟和自有测试素材。

## 五条底线

1. 两分钟约束通过实际音频、镜头时间线和最终帧数兑现，不靠凑字数或最后强截。
2. 故事质量、角色一致性、动作完整性与技术可播放性分别验收。
3. 每个镜头、音频、参考图和成片都有版本；局部修改不能静默覆盖已确认版本。
4. 超时不等于失败；付费任务结果未知时先核对，不能直接重复提交。
5. 外部参考资料仅作为资料，不具备修改系统规则、读取密钥或执行任意代码的权限。
