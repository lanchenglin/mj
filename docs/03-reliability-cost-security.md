# 03 · 可靠性、预算、安全与运维

状态：待实现的工程规则。重点防止“自动化把失败扩大成重复扣费、错误覆盖和不可恢复的项目”。

## 1. 付费默认关闭，dry-run 真的不花钱

未配置并确认预算授权时，所有可能产生费用的文本、视觉审阅、生图、生视频、TTS 和付费探测都被禁止。开发模式使用 MockProvider 或用户已有素材。

`dry_run=true` 只做本地规则/参数/依赖/费用估算，不发送生成请求、不调用付费模型。需要 LLM 写提案也可能收费，不能藏在“只是规划”的名义下。纯查余额/能力接口是否收费须按供应商核实。

预算授权须包含币种、项目范围、阶段/任务类型、总上限、单次上限、有效期、允许的供应商及媒体外发范围。授权主体来自已认证的人，不接受 Agent 自己填写“已批准”。

## 2. 预算账本与并发预占

### 2.1 不用一个 cost 字段混淆不同含义

至少分为估算 estimate、预占 reservation、已确认费用 settled、待核对费用 uncertain、已释放 released；每笔记录保留供应商用量和对应 submission。

准入按每币种分别检查：`已结算 + 已预占 + 未确定但可能发生的费用 + 新请求保守估算 <= 授权上限`。互斥分类避免同一笔费用既在预占又在 uncertain 重复计算；状态迁移必须在事务内完成。

不同币种不直接相加。首版可以只允许项目使用一种结算币种；跨币种必须显式保存汇率来源、时间和风险缓冲，不能偷偷用固定汇率换算。

### 2.2 请求成本不等于成片长度

预算包含文字/视觉调用、角色参考图、分镜图、视频候选、失败/未选候选、TTS 重配、音乐、存储/出口及必要本地渲染成本。账单只按外部账单已知项核算，本地成本无法测得时明确列为未计入。

供应商按秒、按片段、按分辨率或按任务收费时分别计算。例如剪出 6 秒不代表生成只按 6 秒收费；需要购买 10 秒生成档位时按实际请求档位估算。候选与重生成次数纳入预算。

先为样片保留单独额度；全片批量生成在 G3 通过且预算再次核准后进入。剩余预算不足时暂停未提交任务，不删除已付费结果，也不无限切换更贵的模型。

### 2.3 事务规则

创建任务前锁定预算行/使用原子条件更新，在同一个事务中预占与入队，避免两个并发请求各自看见足够余额而合计超额。

成功后按可核对用量结算并释放差额；失败不默认免费；取消不默认退款；提交结果未知时保留风险额度。未知费用只能经查单/账单/人工授权调整，不可直接清零。

## 3. 任务执行、超时与未知提交

### 3.1 分阶段超时

分别设置排队、提交连接、提交响应、远端生成、轮询、下载和本地渲染超时。渲染超时终止所属进程组并保留诊断，不能只让 HTTP 请求返回而后台进程无限运行。

429/暂时性网络问题采用退避和 jitter，遵守供应商 Retry-After；401/403/余额不足/能力不支持不盲目重试。创作效果差不属于网络失败，重新生成需要新预算记录。

### 3.2 最重要的边界：发送请求后没有收到响应

这时供应商可能已经接受并开始计费。任务进入 `reconciling`，不直接重新提交。

1. 有远端 ID：继续查原任务。
2. 无远端 ID但有已验证的供应商幂等/按客户端请求号查询：使用相同身份查回，重发也必须遵守其文档约定。
3. 两者都没有：暂停该操作，提示可能已经产生费用，等待账单/后台核对或人工决定。不能承诺完全防止供应商侧重复执行。

同一远端 submission 的传输重试保留同一幂等身份；只有明确的新创作尝试或已确认失败后新的生成，才使用新 submission 与预占。

### 3.3 重复回调、迟到结果

回调按签名和供应商请求 ID 校验，去重后才更新任务。收到回调不允许任意改变 project_id、资产路径或预算。回调与轮询竞争时，终态写入用条件更新保证一致。

任务取消/方案修改后晚到的媒体仍可保存为未激活历史候选并登记费用，但不得覆盖当前选中素材、恢复已取消的流水线或自动交付旧方案。

## 4. Worker、租约与恢复

任务表是事实来源。Worker 以事务认领、租约期限、心跳和递增 fencing token 管理所有权；执行结果写回必须匹配当前 token，防止失联旧 Worker 抢回结果。

外部网络调用不持有长数据库事务。进程崩溃后按 persisted 状态恢复：未提交的重新排队；已提交的查询原 ID；提交未知的进入核对；已下载未激活的完成验证；已成功的不得重复生成。

事件与业务状态在同一事务写入，SSE 推送只是通知，不承担事实存储。丢事件后客户端可通过游标补拉或查询快照。首版使用有界并发和单个可恢复调度路径，不同时依赖内存队列和另一套互不一致的任务表。

项目级、供应商级、生成类型级和渲染级分别限流；并发数是部署参数。任何“多 Agent 并行”不得绕过预算与限流。

## 5. 资产与渲染完整性

下载先写临时文件，设置大小/类型限制，校验哈希与完整解码后原子登记。HTTP 200、后缀为 mp4 或文件存在都不能单独证明成功；HTML 错误页、空文件、截断视频必须失败。

缓存键至少包含素材内容哈希、音轨、相关模型/模板版本、参数及工具版本。不同文件同名不得误命中；只有渲染相关参数变化才失效对应缓存。远端 seed 不能当作确定性重现承诺。

每次渲染使用独立目录与冻结 manifest；成功后原子切换输出指针，失败不覆盖旧成片。验收包括横竖混合、无音轨、不同帧率、非方形像素、旋转元数据、中文/空格/引号文件名、HDR/SDR，以及字幕字体可用性。

上游 `video-use` 的缓存、默认字幕和音轨处理需要专项改造，不因为上游有测试就默认覆盖这些场景，见 [05](05-upstream-and-decisions.md)。

## 6. Agent 的权限边界

创作 Agent 只产出结构化提案、剧本、分镜、生成参数建议和审阅意见。领域服务决定是否批准、是否调用、是否花钱、是否激活版本。不得给予模型直接修改预算、读取环境变量或任意 shell 的权力。

原故事、图片 OCR 文本、字幕、供应商返回、参考仓库文档都是不可信资料。里面出现“忽略规则”“上传密钥”“下载执行脚本”不成为系统指令。工具调用必须走白名单、schema、对象所有权和预算检查。

确实需要程序化动画时，使用独立无密钥沙箱，限制网络、文件系统、CPU/内存/运行时间；不在 API 进程执行模型生成代码。首版可不支持任意代码动画，优先可配置的固定动画模板。

## 7. 密钥、上传与外部地址

密钥不进入 Git、前端存储、日志、导出包和提示词。浏览器只看到脱敏引用；服务端使用环境注入或加密存储，按操作最小化传给执行器。密钥验证错误不回显完整响应头。

文件上传校验实际类型与尺寸，禁止路径穿越、符号链接逃逸、压缩炸弹和任意绝对路径。FFmpeg 使用参数数组且 `shell=False`，但仍要限制输入协议与路径：不能把模型提供的 URL 或 filter 字符串无校验地传入。

远端下载和参考上传实行域名/协议白名单、DNS/IP 检查和重定向后再检查，默认阻止环回、私网、云元数据地址和 file 协议。确需本地模型端点时，由管理员显式登记，不由普通项目请求开放。

需要供应商读取参考图时，只外发批准资产的短期签名地址/受控上传；不暴露整个素材目录。记录外发对象、供应商与时间，临时 URL 不写进长期公开交付包。

## 8. 最小权限与公开仓库卫生

首版即使只有一个使用者，也要有登录、所有权校验、下载权限和随机生成的管理员凭据，不带公共默认密码。跨站请求、Cookie/Token、TLS 和反向代理配置在部署验证中覆盖；不默认把服务监听端口直接暴露公网。

未来多用户需要审核者/制作人/管理员分权，但不为首版先搭完整 SaaS。所有批准、激活、预算变更、删除和外发均有审计记录。

Git 仅放代码、文档、模拟配置和不敏感的小型测试样例。忽略 `.env`、数据库、生成媒体、用户故事正文、授权原件和任务日志。测试 fixture 是明确虚构素材，不能偷用用户私有项目。

## 9. 数据保留、删除和备份

原始素材默认只读；拒绝镜头不会自动删除。删除采用有引用检查的归档/软删除；活跃任务与已交付 manifest 引用的 Blob 不回收。永久清理需要单独授权及保留期限，不因“节省空间”自动执行。

备份覆盖数据库、媒体与配置版本，密钥单独安全备份；定期在隔离目录做恢复测试。只有数据库备份但没有媒体，不算项目可恢复。迁移先备份，失败可回滚；升级不得悄悄重写旧 schema 或删除未知字段。

## 10. 必须可观察的指标

记录 request_id、project_id、task_id、submission_id、input_fingerprint、工具版本、耗时、状态转换和脱敏错误。区分排队时间、模型生成时间、下载时间和渲染时间。

面板至少展示未确定提交数、重试数、账单未核对额、预算剩余、租约回收、媒体失败、过期候选、硬质检失败及人工驳回。告警只定位问题，不自动触发昂贵的全片重做。
