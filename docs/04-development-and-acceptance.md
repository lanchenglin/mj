# 04 · 开发路线、验收标准与风险清单

版本：v0.1。只有 M0 的规划文档属于当前交付；M1–M5 均未实现、未测试、未接入真实生成服务。以下按成果与依赖排序，不给未经测量的工期或单片费用承诺。

## 1. 开发原则

先打通可检查的纵向流程，再增加模型数量和界面复杂度。最早的真实验证必须包含人物动作和相邻镜头，不以“页面打开”“工具可用”“生成一张图”替代漫剧能力验证。

付费验证须有人工确认的样片预算；未授权时可完成本地/模拟测试，但必须标记“真实模型效果未验证”。不通过模拟数据宣称已经生成作品。

## 2. 阶段路线

| 阶段 | 交付 | 进入下一阶段的条件 |
|---|---|---|
| M0 设计基线 | 产品、流程、契约、风险、上游来源、规划样例 | 文档可追踪、边界清楚；当前仓库所处阶段 |
| M1 可运行骨架与后期验证 | API/Web 最小页面、PG 迁移、项目/版本/任务/预算基础、MockProvider、选定 video-use 移植点、无声视频+中文配音合成 | 本地测试不依赖外网；任务/预算原子性可测试；本地 15 秒合成与可恢复执行通过 |
| M2 创作与资产闭环 | 三方案、结构化剧本、角色/场景/道具设定、声音试听、分镜表、完整动态分镜预演 | G1/G2 有版本绑定；任意镜头能追溯到节拍/人物/参考；真实与临时素材区分 |
| M3 15 秒真实样片 | 一个已验证的生图/参考方案、一个视频适配器、一个中文 TTS 适配器、相邻镜头真实动作、审阅和费用报告 | G3 通过，关键动作和人物稳定，实际费用可核对；不能仅用静图合成过关 |
| M4 两分钟首版 | 分镜批量生产、候选审核、局部重做、实际音频驱动的 3600 帧时间线、多轨混音、字幕、完整 QA 与项目包 | G4 通过；整集观看通过；关键故障注入与恢复通过 |
| M5 增强与产品化 | 更多供应商/表演能力、剪映导出、多集资产复用、协作、性能与发布打包 | 每项新增能力单独验证，不破坏已通过的首版 |

M1 的后期验证复用合法本地合成/测试素材，不必先付费生视频。M2 的真实文字/图片/TTS 调用同样需要授权；可以先用模拟接口完成交互。M3 样片可复用到 M4，避免重复付费。

## 4. 两套验证素材

### 4.1 离线工程素材

用程序生成或有许可的小型图片/视频/声音，涵盖无音轨、不同 fps、旋转元数据、横竖混合、中文路径、故意截断文件、连续音频与明确静止段。用来检验系统，不评价模型画质。

### 4.2 真实创作样片与两分钟样例

采用同一原创短故事进行 15 秒样片与 120 秒制作。首版主样例通过后，再用另一种节奏/画风任务复核可泛化性，避免把所有逻辑写死在一个故事里。

仓库 [120 秒分镜规划](../examples/120s-storyboard.plan.json) 仅提供 20 镜头、3600 帧的数学与语义结构样例。没有绑定任何真实媒体或 measured duration，不能直接生成“通过”的生产报告。

## 5. 工程验收矩阵

| 用例 | 场景 | 预期行为 |
|---|---|---|
| T01 | 预算未设置，尝试真实文本/生图/视频/TTS | 拒绝；记录零外部调用 |
| T02 | 同幂等键重复提交相同请求 | 返回同一操作，不新增预占或远端 submission |
| T03 | 同幂等键提交不同正文 | 409 冲突，不覆盖 |
| T04 | 并发请求合计超过预算 | 只有合法额度内的请求入队，账本一致 |
| T05 | 供应商已接收但响应超时 | reconciling；查原任务，不盲目新建 |
| T06 | 无远端 ID、无查单/幂等能力 | 暂停并明确未知计费风险，不伪装“安全重试” |
| T07 | Worker 在提交后/下载后/激活前崩溃 | 按持久状态恢复，不重复收费，不丢历史 |
| T08 | 回调重复、乱序或签名无效 | 去重/拒绝；终态一致，不跨项目更新 |
| T09 | 取消后收到成功结果 | 保存为未激活候选并核对费用，不自动继续生产 |
| T10 | 旧任务晚于新版本完成 | 旧候选不覆盖当前激活版本 |
| T11 | 相同文件名但内容/音轨改变 | 缓存正确失效，不使用旧字幕/切点 |
| T12 | 生成视频无音轨 | 通过独立音频总线合成，不因 0:a 缺失失败 |
| T13 | 横竖、不同帧率、SAR、旋转混合 | 规范化到项目画布与帧率，主体与字幕保持可读 |
| T14 | 中文标点、数字、人名、长字幕 | 与声音对应、断行正确，无英语式机械空格 |
| T15 | 连续对白跨多个视觉切点 | 不吞字、不随画面反复音频淡化、不抢话 |
| T16 | 6 秒+6 秒镜头重叠 0.5 秒 | 时间线覆盖 11.5 秒；不是错误报告 12 秒 |
| T17 | 最终目标 120 秒、30 fps | 视频解码 3600 帧；音频内容对齐且无台词截断 |
| T18 | subject_action 镜头只返回静图推拉 | 动作合同不通过，不自动接受降级 |
| T19 | API 返回 HTML、空视频或损坏下载 | 媒体校验失败，不产生已交付成片 |
| T20 | 修改字幕样式 | 仅触发必要字幕/合成/质检，不重新生视频 |
| T21 | 更改角色服装或台词长度 | 展示准确影响范围；旧批准失效；历史保留 |
| T22 | 恶意故事提示、URL、路径或 ffmpeg 参数 | 无密钥读取、无任意 shell、无内网 SSRF、无路径逃逸 |
| T23 | DB/媒体备份恢复到隔离环境 | 项目版本、任务、账本与交付素材一致可读 |
| T24 | 导出包检查与旧版本读取 | 无密钥/签名 URL/绝对私有路径；哈希与 manifest 一致 |

T01–T24 是待实现用例，本次未运行这些应用测试。纯文档链接/JSON 检查与应用验收分开报告。

## 6. 创作品质验收

至少逐项人工评价：故事因果与结尾、人物身份与状态、动作完整性、镜头空间与节奏、声音表演与字幕、文画对应。可使用 0=不可用、1=需修改、2=可交付的内部记录方式，但分数不能抵消严重问题；主角换脸、关键台词错误、动作缺失等阻塞项必须修复或重新批准改稿。

模型审阅提供定位和证据，不自行宣布“风格一致率 100%”。抽帧无法完整验证动作，动作镜头需要观看对应连续片段；整体故事需要从头看完。审核通过必须指向同一版媒体与时间线。

首轮有效率、单镜头尝试数、费用、总耗时先测量，再设运营目标。没有真实数据时，报告“尚未测得”，不引用其他项目 Demo 的费用来保证 MJ 的成本。

## 7. 风险与预案

| 风险 | 提前检查 | 预案 |
|---|---|---|
| 人物身份漂移 | 同角色跨景别/光线样片 | 重做参考、降低冲突提示、选片；不能承诺 seed 解决 |
| 复杂动作失败 | 在样片放最难动作而非片头 | 拆动作/换机位/换能力；改动需要确认 |
| 音色或口型不稳定 | 固定声音样本与对白方式 | 首版优先旁白/有限对白，口型能力单独验收 |
| 视频成本失控 | 记录所有候选与重生成 | 样片先行、预算硬门槛、单镜头上限、暂停核对 |
| API/模型变更 | 固定模型配置与能力验证日期 | 合同测试、版本迁移、重新验证，不偷偷切模型 |
| 上游许可证不适配 | 逐文件来源登记 | 不导入受限代码；改用独立实现或取得授权 |
| 用户觉得“只是 PPT” | 动作合同和真实样片 | 明确静态用途；人物动作镜头必须真的有动作 |
| 120 秒牺牲故事 | 全长 animatic 先审 | 改稿和节拍，不最后粗暴裁掉结局 |
| 前端过早复杂化 | M1/M3 验收只看关键闭环 | 分镜表优先，无限画布和专业编辑器后置 |
| 迁移或清理丢素材 | 引用追踪、保留策略、恢复演练 | 原始媒体只读、软删除、备份后迁移 |

## 8. 开工前待落实，但不阻塞当前文档交付

A. 首个真实样片的题材与画风；B. 预算币种/额度及测试授权；C. 文本/图片/视频/TTS 账户可用能力；D. 部署平台与存储；E. 未来是否对外提供软件及许可证选择。

这些事项不预先替用户决定。开发可先完成离线契约、模拟、UI 与渲染验证；在真实调用前落实 A–D，分发代码或集成受限依赖前落实 E。

## 9. 每阶段完成报告格式

报告应包含：实现范围、变更提交、测试命令与真实结果、样片/成片路径及 manifest、实际供应商/模型配置版本、总生成用量与费用、失败/未知提交、未实现项和下一阶段准入情况。

区分“文档写了”“代码存在”“测试通过”“真实样片通过”“完整成片通过”五种状态。不得把其中任何一层替代后一层。
