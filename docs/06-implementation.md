# v0.2 实现与运行说明

## 实际范围

本次从设计仓库重新实现。Python 模块包括 contracts（输入契约）、db（项目/修订/素材/审批/预算/任务/事件）、domain（事务准入）、providers（生成适配）、worker（租约与任务）、media（本地渲染）、app（认证和 HTTP）、cli（启动）。网页提供项目、策划、设定、分镜、素材、任务、音轨、预算和历史操作。

这不是“只做了静态界面”：页面调用真实 API，持久化到数据库，长渲染由 Worker 执行。也不是已通过真实漫剧质量验收的工业版本：本次没有授权账户、实际 AI 视频、真实 TTS 或账单。

## 与原大纲的明确差异

| 项目 | v0.2 实际情况 |
|---|---|
| 前端 | 原生 HTML/CSS/ES modules，不是 React/TypeScript；无 npm 构建依赖，后端接口可供后续重构使用 |
| 数据库 | PostgreSQL 生产路径 + Alembic；SQLite 严格限离线演示/测试；本次只实测 SQLite |
| 时间线 | 整数 fps、整数视频帧、48k 音频采样；硬切、静帧/摄像运动、contain/cover；未实现任意有理数 fps、复杂转场、速度曲线、叠加轨 |
| 角色一致性 | ID、设定、参考图、版本与人工审核，不是自动人脸识别或一致率算法 |
| 配音 | 每镜头独立语音，另可添加跨镜头连续音轨；没有多声道角色自动对话调度/口型模型 |
| 字幕 | 中文断句，按实测语音时长分配句段；不是词级强制对齐；需终审 |
| 回调与取消 | 采用主动轮询，无外部回调入口；取消只停止本地采纳，远端任务继续核对，不主动承诺退款 |
| 账本 | 任务预占/待核对/结算 + 事务审计事件；不是自动对账平台，实际账单人工登记 |
| 备份/恢复 | 提供运维步骤；数据库/媒体灾备演练尚未实测 |
| 交付包 | MP4、SRT、分轨、JSON 时间线/工作区、哈希 manifest；尚未实现剪映草稿和交付包一键重新导入 |
| 性能 | 单用户、单 API、每个 Worker 一次一个任务；PG 可扩进程但尚未压测；不适合作为公共多租户服务直接上线 |

为了先得到可运行且不依赖前端网络安装的交付，采用原生网页而非最初建议的 React。这个选择不改动原创漫剧目标，不把旧方案删除后冒称全量达成。

## 不花钱地检查流程

初始化 `.env` 后运行 `serve --with-worker`。创建演示项目→编辑剧本→保存→角色设定→分镜→完整预演。等待任务完成后到“声音与合成”看输出。所有演示画面清楚标记 MOCK；模拟 TTS 是测试音。可上传自己有权使用的视频/图片/音频，审核、关联到镜头后实际合成。

正式 `subject_action` 镜头需要被人工标记为符合动作的非模拟视频；这只是审核记录，不意味着算法自动证明了动作质量。任何真正发布前，都应连续观看动作镜头和完整视频。

## 配置生成服务

`providers.example.json` 仅展示字段。不要原样启用，模型名、接口账户权限与预占金额需要实际确认。`models.text` 必须支持 JSON object 格式的 chat/completions，返回 `{"data": ...}` 并通过 Pydantic。图片需要返回 PNG，配音需要 WAV。

fal 视频当前要求单张分镜参考图。先通过生图或自有图片完成角色与场景组合，在素材库审核，并把素材 ID 放入镜头的 reference_ids。不要把多个角色参考图直接当作此视频适配器支持的多参考能力。时长取管理员配置中不短于镜头需求的最小档位，价格应按供应商实际档位预占，而非成片秒数。

先批准 G1，建立设定与分镜，再批准 G2。G3 前的视频生成勾选“代表性样片”；制作 10–20 秒连续样片时填入相邻镜头 ID。真实生成素材需审核、关联后再合成。G3/G4 的检查项需要用户观看媒体后填写，不能由模型勾选。批量正式视频准入要求 G3，并核对视频供应商配置与样片来源；首版 UI 逐镜头提交，没有全片一键生产按钮。

在生产 `.env` 中配置 key_env 指向的密钥，设置外发和预算授权，重启 API 与 Worker。配置文件读取在进程启动时完成。更改服务商/模型不要在同一冻结任务内偷偷替换，创建新任务并重新核验必要样片。

提交没有回应或返回结构不明时会保守保留风险额度。缺少可查的远端 ID 就不能自动恢复；请到供应商控制台核对，再记录费用。此版本没有“放弃未知任务后自动免费重试”的功能。

## 安全与运维

仅面向自己的可信工作区。绑定环回地址不等于完整生产防护。外部部署必须配置 TLS、Origin、Secure Cookie、反向代理请求体上限、请求频率限制、容器资源限制与出站网络策略。

上传端在流式复制时限制文件大小，但 HTTP multipart 解析发生更早，因此应在代理层再限体积与超时。供应商仅允许 HTTPS 指定域名、拒绝重定向、检查公网 DNS；这不等于已消除 DNS 重绑定风险，生产应以网络层出站规则锁定可信供应商。导出 ZIP 仍在 API 工作线程执行，大项目应迁移到独立导出任务。上传/生成资源不永久自动删除，管理员需监控磁盘。

暂停生产和 API 写入后备份 PostgreSQL、媒体卷和配置，密钥单独保管。恢复到隔离环境，对照 manifest 哈希与版本核验。升级前备份，再运行 alembic；不要在有业务数据的生产库直接 downgrade base。当前提供初始迁移，但没有完成生产灾备演练。
