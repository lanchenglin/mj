# 00 · 产品大纲：两分钟原创漫剧

版本：v0.1；日期：2026-09-15；状态：设计基线，待开发验证。所有“应/必须”是 MJ 的拟定验收规则，不代表功能已经实现。

## 1. 目标与定位

MJ 面向原创故事短片制作。输入一个构想、短篇故事或有权改编的文本，输出约两分钟中文漫剧及其可继续编辑的制作项目。首要价值是故事成立、人物可辨、声音自然、镜头连续、修改可控，而不是减少到一个没有审核环节的按钮。

本期只做“从故事生成原创漫剧”。“已有影视素材转解说”另设未来路线，不在首版实现视频搜索、整片剧情检索、人脸匹配、去水印或原片自动混剪。两条路线未来只共享资产、声音、时间线和渲染等公共能力。

### 成功必须同时满足三类条件

1. **作品条件**：人物有目标和阻碍，冲突可理解，转折有铺垫，结尾有交代；情绪不是旁白空讲，画面确实表现关键事件。
2. **制作条件**：身份、服装、场景和道具不无故变化；对白归属清楚，关键动作完整；单镜头可替换，不用整集重做。
3. **系统条件**：时长可测、失败可恢复、预算可追踪、任务不可重复误扣、每次交付可追溯到固定版本。

播放成功只能证明部分技术条件，不等于作品通过。

## 2. 本次已经确认与仍属建议的事项

**用户已确认**：先做两分钟原创漫剧；基于现有 Git 项目开发；使用 mj 仓库；当前先完善并提交大纲。

**建议默认值，可在开工前修改**：Web 工作台；中文；单用户/单工作区；9:16、1080×1920、30 fps；每集 120 秒；2–3 个主要角色、2–3 个主要场景、约 18–26 个镜头；模型 API 生成、本地或服务器合成。

**未确认事项**：实际预算和币种、首个模型供应商及账户、目标画风、服务器规格、未来是否对外提供软件、MJ 自有代码许可证。未确认预算默认禁用所有付费调用，不把建议额度当成用户授权。

默认限制是降低首轮验证复杂度，不是永久上限。人物更多、长对白、复杂打斗可以提案，但必须给出额外成本和制作风险，不能静默删改故事。

## 3. 成片模式：先做什么，不冒充什么

### 3.1 首版：旁白驱动的原创动态漫剧

以原创情节和角色为中心，旁白组织叙事，允许少量人物对白；关键行为通过实际人物动作呈现。气氛、回忆、建立场景等镜头可以采用经过确认的静帧、分层动画或镜头运动。

这不是“随便几张图配旁白”的同义词。每个镜头必须声明运动合同：

| 要求 | 含义 | 可接受的实现 |
|---|---|---|
| none | 构图停留本身就是表现 | 确认过的静帧/定格 |
| camera | 只需要推拉、平移或景深层次 | 可控镜头动画/分层运动 |
| subject_action | 角色必须完成可见行为或表情变化 | 能呈现该行为的生成视频或角色动画 |
| lip_sync | 看得见的说话必须与声音对应 | 经验证的口型方案；首版仅探索，不承诺普遍支持 |

不能用 camera 满足 subject_action，不能用字幕代替 lip_sync。模型不支持时，任务进入阻塞或申请修改分镜，不能擅自降级。输出记录每个镜头的实际实现类型，不以单一“全动态”标签掩盖差异。

### 3.2 后续增强

多人物对白、精确口型、复杂交互动作、全动态风格和连续多集。必须先通过代表性样片与专项验收，不能只把模式开关加到界面上。

## 4. 用户旅程与功能大纲

### 4.1 创建项目与需求澄清

填写故事构想、受众、题材、基调、画风、时长、比例、声音方向、必须保留/避免的内容和预算。上传参考图、已有角色设定或授权证明。缺项先采用明确标注的建议，不替用户虚构授权、素材或账户能力。

首版输入支持文本与本地图片/音频/视频素材。PDF、Word、长篇章节批量导入可后置；不为初版引入不必要的解析依赖。

### 4.2 策划与剧本

默认生成三个有实质区别的方案：至少在人物视角、核心冲突、叙事结构或结尾机制上不同，不能只换标题。用户可以选一个、融合明确元素或重新提案。原候选保留，可对照修改，不能每次覆盖。

剧本拆为叙事节拍、旁白/对白、可见行动、情绪变化和必要声音。必须标明“说了什么”和“画面实际发生什么”，避免文画重复或关键信息只存在于提示词里。

### 4.3 角色、世界和声音设定

角色有稳定 ID、外观锚点、服装版本、性格与动机、关系、声音档案、可变状态。场景有位置、空间关系、时间、光线和可用机位；关键道具有初始状态与转移规则。

参考资产可多角度、可重做、可版本对比。正反面/表情图按实际分镜需要准备，不强制所有项目支付全套设定费用。相同随机种子不是身份一致性的验收依据。

### 4.4 分镜与预演

分镜表展示镜头功能、景别、角色、动作、对白、声音、时长、参考资产、进入/退出状态、前后镜头衔接方式及生成成本。先用分镜图和声音做完整预演，确认故事与节奏，再大量生成视频。

“场景”“镜头”“一次模型生成片段”“时间线片段”必须分别管理。一个生成片段可提供多个合法截取段；一个镜头也可能需要重生成，不能用 API 的 5 秒/10 秒档位反过来决定剧情。

### 4.5 单镜头生成与修订

显示候选视频、使用参数、生成状态、实际时长和费用。可以重做画面、重做动作、重做声音或修改剪辑，不把所有修改统一处理成整集重跑。切换候选需要显式激活版本；失败和未选用候选仍保留成本及来源。

### 4.6 时间线与终审

首版采用分镜列表+预览+基础时间线，不开发完整专业非线性编辑器或无限画布。支持排序、裁剪、批准的节奏调整、旁白/对白/音乐/音效音量、字幕样式与版本回退。

技术问题和创作问题分栏；未通过项定位到镜头、帧或音轨。最后由用户确认版本，导出，不自动发布社交平台。

## 5. 工作台页面

| 页面 | 用户需要完成的事 |
|---|---|
| 项目首页 | 查看制作阶段、当前批准版本、预算/预占/实际费用、阻塞原因 |
| 策划与剧本 | 对比三个方案，编辑节拍和台词，确认变更影响 |
| 资产设定 | 角色/场景/道具/声音卡片，参考图版本，授权状态 |
| 分镜工作台 | 表格/卡片、进入退出状态、预估时长、候选预览、局部重做 |
| 声音与预演 | 试听、发音修正、对白归属、音轨与完整动态分镜预览 |
| 生成任务 | 队列、提交状态、远端任务 ID、取消、核对、费用与错误 |
| 时间线与质检 | 实际时长、字幕、音轨、连续性告警、切点检查 |
| 导出与历史 | 固定版本交付包、清单、审核报告、旧版本只读访问 |
| 设置 | 密钥引用、供应商能力、预算策略、存储、导出规格 |

每个阻塞提示同时说明原因、能否重试、重试是否可能产生费用、需要谁确认。多个标签页的编辑不能静默相互覆盖。

## 6. 交付包

必须交付 `final_clean.mp4`、按需烧录字幕版、UTF-8 SRT、实际采用的配音/音乐/音效分轨、版本化时间线、分镜与资产清单、质检报告及费用报告。

项目包使用相对资产引用与文件哈希；不包含 API Key、临时签名 URL、用户绝对路径、供应商原始敏感响应。大媒体留在项目存储，不提交 Git。剪映草稿是后续兼容性模块，不作为首版唯一交付格式。

## 7. 范围与优先级

**P0 必须有**：一个原创项目端到端；三个候选方案；可编辑结构化剧本；稳定角色/场景资产；分镜和声音预演；真实动作样片；按镜头生成、审核、替换；120 秒时间线；中文配音/字幕/多轨混音；预算、版本、恢复、最小权限；成片与项目包。

**P1 增强**：多个供应商可切换、更多声音表现、批量集数、跨集资产复用、剪映草稿、较丰富转场、协作审核。

**暂不做**：开放 SaaS 计费、多租户市场、无限画布、模型训练平台、整片影视解说、自动营销发布、未经许可的声音克隆。

底层数据保留扩展空间，不提前实现全部未来产品。技术架构见 [02](02-architecture-and-contracts.md)，交付阶段见 [04](04-development-and-acceptance.md)。

## 8. 衡量指标

首轮记录而非虚构：一遍生成可用率、每镜头平均尝试次数、通过质检的有效视频秒数、总外部费用、每成片秒费用、每个阶段等待/处理时间、用户修改次数和整集制作耗时。

不能仅用成片长度或成功 HTTP 响应评价系统。质量阈值须经样片标定；人脸/图像相似度只提供提示，不宣称“100% 角色一致”。商业模型是否值得持续使用，应根据相同题材与动作任务下的有效片段成本比较。
